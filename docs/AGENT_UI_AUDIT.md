# Agent UI Audit

Дата: 2026-07-28

## Что уже улучшено

- Убрана тестовая заглушка из истории чата.
- Добавлен нормальный empty-state для нового диалога.
- Composer стал компактнее: поле ввода больше не занимает почти весь первый экран.
- Правая панель плана стала read-only и получила пользовательский заголовок `Ход выполнения`.
- `Decision Timeline` скрыт из обычного пользовательского UI.
- Убрано постоянное обновление `Decision Timeline` из общего refresh формы.
- Исправлен потенциальный performance-баг: инкрементальная отрисовка чата больше не зависает на уже отрисованном `УИД`.
- CDP UI runner теперь выбирает свободный debug port, поэтому headless E2E можно запускать параллельно.
- Новый диалог создается с выбранным типом диалога, а не только как `Агент`.

## Проверенные сценарии

- `web_agent_skill_e2e.py`: обычная форма `ИИ Агент -> Отправить`, выбран пользовательский skill, в prompt попал `target_object_name`.
- `web_skills_negative_ui.py`: пустое описание, битый JSON, запрет перезаписи system skill.
- `web_agent_modes_e2e.py`: реальные запуски агента через UI:
  - metadata/read-only сценарий;
  - `Запрос1С`/RunQuery сценарий;
  - write-skill сценарий без записи без подтверждения.

## Наблюдения

- В web-client значение textarea не всегда попадает в `document.body.innerText` до blur/change, хотя 1С модель формы получает текст и агент запускается. Поэтому UI E2E проверяет результат через bridge-логи.
- Поле режима выглядит как обычный enum input. Для пользователя это слабый affordance: режим лучше сделать явным сегментированным переключателем или отдельными action chips.
- Даже после визуального переключения в `Запрос1С` стоит дополнительно проверить запись `ТипДиалога` в справочнике: E2E показывает, что real RunQuery выполняется, но представление диалога в логах все еще может выглядеть как `Агент`.
- Правая панель плана полезна, но должна быть collapsible: в длинных ответах она отъедает горизонтальное место.

## Следующие улучшения

- Перенести composer вниз формы или сделать визуально закрепленным снизу, чтобы форма была ближе к современным AI agent интерфейсам.
- Заменить enum input режима на явный переключатель: `Агент`, `Запрос 1С`, `Безопасный просмотр`, `С записью`.
- Добавить пользовательские status chips: `План`, `Выполнение`, `Ожидает подтверждения`, `Готово`.
- Сделать правую панель `Ход выполнения` сворачиваемой; по умолчанию показывать только короткий progress.
- Добавить отдельную кнопку/ссылку `Диагностика`, где будут `Лог`, `Decision Timeline`, trace id и prompt details.
- Ограничить первичную загрузку истории последними N сообщениями и добавить `Показать ранние`, чтобы старые диалоги не создавали сотни элементов формы.
- Для write-flow показывать карточку подтверждения с понятными полями: объект, действие, риск, что будет записано, кнопки `Подтвердить`/`Отклонить`.
